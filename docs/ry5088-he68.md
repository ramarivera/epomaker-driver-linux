# HE68 Lite variants

The CLI enables internal IDs **2762, 2883 and 3664** on USB `3151:5029`.
The same product ID also belongs to H60 and unimplemented keyboards; a matching
product ID alone never enables configuration. The backend identifies the internal
firmware ID and checks an explicit allowlist before sending settings commands.

These variants support four profiles with four normal submodes each, Windows/Mac
Fn maps, macros, OS options, 21 main lighting effects, five custom RGB pictures,
magnetic reads, actuation/rapid-trigger updates, DKS/mod-tap/toggle modes, snap
pairing/removal and switch-type selection. Firmware-dependent magnetic bounds follow the
[H60 defaults](ry5088-h60.md). There is no catalog sleep or debounce setting.

## Model-specific evidence

Archive hashes are in [source-releases.json](source-releases.json); the functional
catalog and loader crosswalk are in [model-inventory.json](model-inventory.json).

| 2883 | HE68 Llte | 1a9b921e.js | 4e6e3981.js |
| 3664 | HE68 Lite UK | fdfb6ad0.js | 6db018f0.js |

Each module directly extends the modern base `623d2d52.js` / `17dc9c62.js`.
All three declared 512-byte matrices match between the two installers. IDs 2762
and 2883 share matrices; 3664 has its own normal/Fn/Fn-Mac defaults. The catalog
labels 3664 as UK while its `keyboardLanguageType` value is `german`; the driver
preserves these source facts rather than inferring a regional layout. Snap
removal restores each model's actual default bindings.

All three catalogs declare `isSwitchReplaceable: true` and seven supported switch
names: 高特, 磁玉, 磁玉pro, 磁玉gaming, 天王, 万磁王 and 冰玉. Those values match
between installers. H60 instead declares nonreplaceable switches.

## Switch-type state

The modern base gates switch replacement on the catalog flag (private prettified
macOS base lines 120–124) and reads field `252` as two raw 64-byte pages (lines
1013–1016). Linux therefore reads all 128 switch-type bytes for the three HE68
models. `get-magnetic` retains the complete field in `fields["252"]` and exposes
its numeric per-key value as `slots[].axis_type`, including unknown values such
as 255. It does not silently replace unknown codes with a default switch name.

Actuation, mode and snap writes preserve the entire switch-type field and include
it in readback comparison. Unrelated switch-type changes during those operations
are reported as a readback failure. These operations do not write field `252`.
The vendor base has a separate switch-type write after parameter writes (lines
1451–1463). The CLI's `switch-type TYPE SLOT [SLOT ...]` command selects one of
the catalog's seven names or its decimal code for one or more physical keys.
Each changed slot receives a separate committed field-252 packet; the driver
then verifies the complete magnetic state and all four normal keymap submodes.
Unchanged selections issue no write. Partial writes, profile changes and failed
readback are reported, with no attempt to infer a rollback.

| Name | Decimal code |
| --- | --- |
| 高特 | 0 |
| 磁玉 | 1 |
| 磁玉pro | 2 |

| 天王 | 4 |

| 冰玉 | 33 |

For example, `epomaker --device /dev/hidrawN switch-type 33 1 2` sets slots 1
and 2 to 冰玉. Use `status` for the supported name/code list and `get-magnetic`
for raw per-slot values. Unknown stored codes are preserved on other keys;
unknown requested codes, duplicate slots, padding and Fn slots are rejected.
H60 and HE60 Lite reject this operation because their catalog does not expose
replaceable switches.

The code dictionary is identical in both private main bundles at lines
9720–9753. The complete `保存轴体设置` UI action also matches byte for byte:
macOS 108259 onward / Windows 107171 onward. It changes only the selected
keys' switch property and schedules their magnetic update. Calibration is a
separate workflow (`check磁轴按键校准`, macOS 115125 onward / Windows 114037
onward); this command does not reset calibration, travel, modes or bindings.

## Limits and verification

Tests exercise real CLI dispatch with simulated HID, profile 3/submode 3, both
Fn address fields, magnetic precision, model-specific snap restoration, raw
switch-state preservation, corruption detection and wrong-ID/bootloader gates.
The default matrices were compared byte for byte across the supplied installers.
No physical HE68 round trips have been verified.

Calibration, magnetic configuration recovery, firmware
updates and GUI support remain unfinished. See [migration status](parity.md).
