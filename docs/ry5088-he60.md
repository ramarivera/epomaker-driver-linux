# EPOMAKER HE60, internal ID 3746

This model is `ry5088_jc_gk8149g_1m_8k_ry1049es`, VID/PID **3151:5029**.
It is distinct from H60 3662, HE60 Wired 3691, HE60 Wireless 3692 and the
HE60 Lite models. A matching USB product ID does not identify the model.

The Mac loader selects `fa455a99.js`; Windows selects `bb2c7696.js`. Both
children directly inherit the modern magnetic protocol (`623d2d52.js` and
`17dc9c62.js`) and declare only their three 512-byte matrices. All three arrays
match between the supplied installers:

| Matrix | SHA-256 |
|---|---|
| Normal | `c864e07a8521a009235d8b4632a8cf0f3d3cfd0fa64cee7485cf38b166682aff` |
| Windows Fn | `e7013592b988cbd0b2687bd8716fde7fa3d4fd545dce08209ed4381add3c3a21` |
| Mac Fn | `6929e22667a23a22092f0e201cd862b8464926d6c89d5f85a114be1c2ec2ee23` |

The backend uses these functional matrices from `data/he60-matrices.json`.
It enables four normal profiles with four magnetic submodes, Windows and Mac
Fn banks, macros, magnetic reads and edits, mode definitions, snap pairing,
switch selection, main lighting, five custom RGB pictures, OS controls,
calibration telemetry/sessions and schema-7 backup/restore. Side lighting,
RF version reads, sleep and debounce are not exposed for this model.

## Switch codes and travel limits

The model's exact switch list is `云玉磁轴` and `天青轴`. The vendor enum assigns
codes **93 (5d)** and **55 (37)** respectively. The shared switch encoder maps
the names directly through this enum; no model-specific aliases are present.
Selection writes magnetic field 252 and verifies the field and other state.
Older switch types remain unavailable on this model, and adding these enum
entries does not broaden older models' switch lists.

The explicit `other.travelSetting` metadata is:

| Setting | Minimum | Maximum | Step |
|---|---:|---:|---:|
| Travel/actuation | 0.1 mm | 3.4 mm | 0.005 mm |
| Rapid-trigger press | 0.005 mm | 2.5 mm | 0.005 mm |
| Rapid-trigger lift | 0.005 mm | 2.5 mm | 0.005 mm |
| Bottom dead zone | 0 mm | 1 mm | 0.005 mm |

These model values override the generic RY5088 UI defaults. Wire precision still
depends on firmware, as described in [magnetic protocol](magnetic-protocol.md).
The independent driver rejects values finer than the wire can represent:
0.1 mm below USB version 0300, 0.01 mm at 0300–04ff, and 0.005 mm from 0500.
This intentionally avoids the vendor encoder's truncation of a requested 0.005 mm
rapid-trigger threshold to zero on older firmware. Model bounds still apply on
those versions: travel never exceeds 3.4 mm and bottom dead zone never exceeds
1 mm. Snapshot restoration preserves raw magnetic fields, including inactive or
unknown values; ordinary edits validate the applicable model and firmware limits.

```text
epomaker --device /dev/hidrawN identify
epomaker --device /dev/hidrawN profile 3
epomaker --device /dev/hidrawN switch-type 云玉磁轴 1
epomaker --device /dev/hidrawN magnetic-key 1 --travel 3.4
epomaker --device /dev/hidrawN backup he60.json
```

The tests use independently simulated USB firmware to check model identity,
matrices, switch encoding, bounds, profile/submode routing, calibration dispatch
and complete recovery. This establishes implementation behavior, not physical
hardware compatibility. No model is marked hardware-verified.
