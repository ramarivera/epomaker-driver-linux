# RT85 CLI support

RT85 (internal ID 2895, `yc3123_ss_sn001`) has an initial CLI/backend
implementation. No physical RT85 has been tested. The catalog marks it
`rt85-partial`, not fully supported or hardware-verified.

Supported operations are identification, restricted status, four normal profiles
(indices 0–3), Windows and Mac Fn matrices, four-byte key bindings, and 256-byte
macro slots, sleep timers, still/animated display uploads, clock sync, language
switching, main/side lighting, five custom RGB pictures, OS controls, full
configuration snapshots and factory reset with a recovery copy. Configuration writes use readback checks; display uploads have no
implemented pixel readback. Default matrices are
available through `models.default_matrix(2895)` and its Fn-layer selectors.

The graphical interface still requires Glyph: it has Glyph's geometry and
settings controls. RT85 debounce, system-information display and firmware updates
remain disabled. The backend
checks the complete write batch before sending any command. RT85 status reports
only the migrated capabilities, display dimensions, sleep, lighting and OS settings.
RT85 uses [snapshot schema version 4](snapshots.md) to retain its fourth profile.
The older Glyph-only schemas are rejected for RT85.

```sh
# Select the fourth profile; command paths must come from discovery.
epomaker --device /dev/hidrawN profile 3
# Read its physical-slot matrix.
epomaker --device /dev/hidrawN matrix --profile 3
# Assign HID usage 5 to physical slot 9 in that profile.
epomaker --device /dev/hidrawN key 9 00000500 --profile 3
```

## Installer evidence

Both 3.2.22 installers contain the same three 512-byte RT85 default matrices,
compared byte for byte. The model subclasses define only these matrices:

| Source | Model class | YC3123 parent | Shared keyboard base |
| --- | --- | --- | --- |
| macOS | `00bc95d6.js` | `2cea305b.js` | `623d2d52.js` |
| Windows | `1f766ec6.js` | `c6c9152c.js` | `17dc9c62.js` |

These are paths under the installers' `app/dist/js` assets. The YC3123 parent
supplies upgrade overrides; the key/Fn/macro methods come from the shared base.
Catalog metadata supplies four normal profiles and one Fn profile per OS.
Normal matrix reads use opcode `8a`, writes `0a`; Fn reads/writes `90`/`10`;
macros `8b`/`0b`; active profile `84`/`04`. Packet layouts are those documented in
[glyph-protocol.md](glyph-protocol.md), with profile index 3 additionally permitted.

The functional default arrays are in
`src/epomaker_driver/data/rt85-matrices.json`; vendor program code is not included.
Model limits are enforced in `device.py`, while codec functions retain the Glyph
profile maximum unless their caller explicitly supplies another one.
`tests/test_rt85.py` exercises independent profiles, Fn separation, macros,
readback and rejection of unmigrated operations. CLI and server tests cover fourth
profile selection and refusing RT85 in the Glyph interface.

## Further family work

The `isYC3123` flag alone is insufficient to enable a model. Five catalog models
also declare `isRY6602` and have different product IDs, timing and display formats.
RT75 declares `defaultFnMACMatrix`, unlike the inherited `defaultFnMacMatrix`;
its effective fallback is now traced in [rt75.md](rt75.md), and RT75 core
configuration is supported independently of those defaults.
RT85 itself has a 320×172 display, versus Glyph's 428×142. Display dimensions,
memory limits and vendor feature gates are now used by its upload path.


## Display and sleep migration

Both installers have identical RT85 `other` capability metadata: RGB565 mode,
320×172 dimensions, 6 MiB memory, five still banks, date/clock support and language
switching. Unlike Glyph, RT85 does not declare `canSyncSystemInfo`; opcode `22`
remains unavailable. The model's shared transfer implementation uses `a5` to prepare,
`25` for pixel chunks, `28` for clock and `27` for language switching.
See [display.md](display.md) for memory accounting and transport limitations.

```sh
epomaker --device /dev/hidrawN screen wallpaper.png --fit --bank 5
epomaker --device /dev/hidrawN animation wallpaper.gif --fit
epomaker --device /dev/hidrawN clock
epomaker --device /dev/hidrawN display-language-toggle
epomaker --device /dev/hidrawN sleep 120 240 1800 3600
```

Sleep values are seconds, in Bluetooth, receiver, deep Bluetooth and deep receiver
order. Both backlight timers accept 0–64800; deep timers accept 10–64800. The vendor
UI gates these controls on `sleepBT`/`sleep24` metadata (macOS main bundle pretty
lines 111723–111821). The shared base writes four little-endian uint16 values at
bytes 8–15 with opcode `11` and reads with `91` (protocol lines 219–252).
The Linux driver compares all four returned values and reports a mismatch.

Tests check column-major conversion with the taller RT85 dimensions, exact transfer
bounds, all five banks' index range, capacity for 51 animation frames, oversize
rejection, language/clock packets, sleep bounds and readback failure. These are
simulated firmware tests; physical behavior and persistence remain unverified.


## Lighting and OS options

RT85 and Glyph both reference main-light layout `Ur` in the installers. RT85's
side-light layout is `Kt`, while Glyph uses `Q`. The definitions of `Ur` and `Kt`
match exactly across the Windows and macOS pretty bundles (lines 42385–42480 and
43292–43301). RT85 therefore exposes the same 22 main-light mode names as Glyph,
and these five side effects:

| Side mode | Maximum speed |
| --- | --- |
| off, solid | no speed control in the vendor UI |
| breathing, neon | 3 |
| wave | 4 |

The CLI uses zero as the default speed for off/solid. RT85 rejects side snake;
Glyph retains side snake and its wave-speed maximum of 3. Main speed is encoded
as `4-speed`, whereas side speed is sent directly. Writes compare response bytes
1–7 against the requested packet; this checks mode, speed, brightness, flags and
RGB together. Hardware normalization and physical appearance remain unverified.

The shared base's `_setLightPic` writes seven packets totalling 378 RGB bytes,
with the commit flag on the last packet; `_getLightPic` reads six 64-byte pages.
The final six bytes are not writable. RT85's five banks use the same verified
readback and per-slot editing as Glyph. Bank activation uses main mode `picture`
and zero-based `option` 0–4.

The shared `setKBOption` / `getKBOption` and `setAutoOsen` / `getAutoOsen`
methods supply Windows/Mac selection, WASD swapping and automatic OS selection.
Model metadata supplies one Fn layer per OS. The Linux option writer preserves
unrelated response fields, including unknown bytes, and verifies its changes.
The vendor controller reads and dispatches these through `getOther`,
`checkOtherChange` and `checkKBOptionChange` (macOS main pretty lines 115011–115101).

```sh
epomaker --device /dev/hidrawN light wave --side --speed 4
epomaker --device /dev/hidrawN light solid --rgb ff8040
epomaker --device /dev/hidrawN get-picture 4
epomaker --device /dev/hidrawN options --system mac
epomaker --device /dev/hidrawN auto-os on
```

Debounce is intentionally still unavailable on RT85: the vendor UI's
`supportDebounce` requires `other.deBounce`, which its catalog entry lacks.
Full snapshots and factory reset use schema version 4 with four profiles and a
null debounce field. Recovery files are validated and saved before writes; reset
backups include all 256 macro slots.
