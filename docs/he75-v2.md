# RY5088 HE75 V2 (internal models 3518 and 3883)

HE75 V2 has an enabled partial USB backend for two catalog identities. Model
3518 (`EPOMAKER HE75 V2`) uses VID/PID `0x3151:0x5054` and two profiles.
Model 3883 (`HE75 V2 TMR`) uses `0x3151:0x5030` and four profiles. Both have
Windows/Mac Fn layers, magnetic configuration, main layout `S`, side layout
`ei`, and replaceable switches. Hardware remains unverified.

The audited Mac and Windows model modules contain matching 512-byte normal,
Fn-Windows, and Fn-Mac matrices. Their SHA-256 values are:

Both models support the shared magnetic keymap, modes, snap, calibration,
pictures, macros, OS controls, schema 7 backup/restore, and profile-aware
readback. The side-light layout is model-gated as `ei`, with four effects:
Wave, Neon, AlwaysOn, and Off. Wave and Neon accept speed 0–4; brightness/value
is 0–4. RGB and dazzle controls apply to Wave and AlwaysOn. Neon uses its fixed
flag encoding and has no RGB/dazzle control; Off has no value or speed control.
The side packets use the shared `0x08` write and `0x88` read commands, with the
vendor Bit8 write checksum preserving the RGB blue byte.

Switch names and canonical wire codes are model-specific. ID 3518 accepts
`灭霸轴` 43, `白星` 92, and `云玉磁轴` 93. ID 3883 accepts `灭霸轴` 43,
`天霸轴` 62, `精灵王轴` 44, `芭比轴` 61, and `泰山轴` 86. The status display
alias `灭霸轴` → `紫星轴` is retained, while CLI input uses canonical names.
Knob slots are normal-layer bindings: ID 3518 volume up 91, volume down 90,
mute 92; ID 3883 volume up 96, volume down 97, mute 98.

ID 3518 catalog sleep bounds are 60–3600 seconds for 24G and Bluetooth, with
Bluetooth deep sleep 600–3600. It has no catalog travel override. ID 3883 has
catalog minima of zero and no finite maximum; the wire fields are uint16 and
therefore limit public timer writes to 0–65535, including deep Bluetooth.
Deep dongle sleep is hidden and preserved unchanged. Its catalog travel range
is 0.1–3.3 mm in 0.01 mm steps. These are source/UI and wire limits, not
physical hardware verification.

The shared schema 7 recovery preserves raw magnetic fields, inactive data,
macros, pictures, lighting, Fn layers, sleep words, and model-specific settings
subject to exact identity and firmware-version checks. USB is the supported
transport. Firmware management, reconnect monitoring, GUI integration, and
physical device verification remain outside this partial backend.
